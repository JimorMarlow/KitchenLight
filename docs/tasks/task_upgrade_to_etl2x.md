# Задача: переход KitchenLight на ETL 2.x и Arduino core 3.x

Статус: план, ждёт завершения работ ETL → ETLTest → Moonshine. Создано 2026-11-24.

## Требования к разработке

- Начинать только после того, как ETL 2.0.0 выпущен и ETLTest с Moonshine на нём собираются
  и проверены: KitchenLight переходит на уже стабилизированный API, а не на промежуточный.
- После каждого этапа собирать `esp32c3`; при добавлении окружений — все.
- Загрузку на плату и монитор выполнять только по явному запросу пользователя.
- В git ничего не коммитить и не пушить; текст коммита готовить по запросу.
- Все изменения записывать в `docs/tasks/task_upgrade_to_etl2x_history.md`.
- Пункты `- [ ]` закрывать только после проверки пользователем.

## Цель

Перевести проект с `etl@^0.9.8` (ветка 0.9, старый API) на актуальный ETL 2.x и на
платформу `espressif32 @ ^8.0.0` (Arduino core 3.x), сохранив поведение: сохранение настроек
в LittleFS, плавное управление яркостью, мигание при старте.

## Предусловия

- [ ] ETL 2.0.0 выпущен (раздел в README, `sync_version.py`, `library.json`).
- [ ] ETLTest собран на 2.0.0 (все шесть конфигураций), `test_all()` проверен на плате.
- [ ] Moonshine собран на 2.0.0 и проверен на устройстве (он ближе всех к webui/настройкам).

## Текущее состояние проекта

`platformio.ini`:

- `platform = espressif32` **без версии** — сейчас подтягивается старый core 2.x; надо зафиксировать `^8.0.0`;
- `https://github.com/JimorMarlow/etl@^0.9.8` — caret держит версию ниже 0.10.0, поэтому
  обновления 1.x/2.x сами не приедут;
- одно окружение `esp32c3` (плата esp32-c3-devkitm-1, `BOARD_ESP32_C3_SUPER_MINI`);
- `-std=gnu++17`, `build_unflags = -std=gnu++11, -Wregister` — совместимо с core 3.x;
- зависимости: GTimer, EncButton, vl53l0x, FileData.

Код:

## Что меняется при переходе (ожидаемый список)

| Область | 0.9.8 (сейчас) | 2.x (после перехода) |
|---|---|---|
| Платформа ESP32 | core 2.x, `ledcSetup`/`ledcAttachPin` | core 3.x, `ledcAttach`/`ledcWrite`/`ledcDetach` (внутри `etl::led`) |
| `data<T>::get()` | возвращает значение | проверить: значение или ссылка; `app_data<T>::get()` — `etl::optional<T>` |
| `data<T>::set()` | `set(data)` | ожидается совместимый overload с источником по умолчанию — проверить |
| `etl::led` | старый PWM-канал | `init_pwm(pin, freq, resolution)` через новое API core 3.x |
| `etl::little_fs` | проверить наличие/сигнатуры | `etl::little_fs::begin()`, `create_dir()` |
| `etl::settings::sender_id` | нет/иначе | появится; на проект не влияет, т.к. подписок нет |
| `etl::shared_ptr`, `etl::clamp`, `etl::vector` | есть | должны сохраниться; проверить по заголовкам |

- [ ] Уточнить у пользователя: остаётся ли только `esp32c3` или добавляются другие платы.

### Этап 1. Платформа core 3.x

- [ ] `platform = espressif32 @ ^8.0.0` в `[env:esp32c3]`.
- [ ] Сборка: ожидаемые ошибки — старый `etl@0.9.8` может не знать `ledcAttach`; это ожидаемо

- [ ] Проверить, что `-std=gnu++17` и `build_unflags` не конфликтуют с core 3.x.

### Этап 2. ETL 2.x

- [ ] `https://github.com/JimorMarlow/etl@^0.9.8` → `^2.0.0` (или `https://github.com/JimorMarlow/ETL@^2.0.0` —

- [ ] Проверить `init()`/`tick()`/`get()`/`set()` по заголовку ETL 2.x, а не по памяти.

### Этап 3. Настройки и файловая система

### Этап 4. PWM и плата

- [ ] Проверить инверсию/яркость на реальной плате (по запросу пользователя).

### Этап 5. Приёмка

- [ ] `pio run -e esp32c3` — успешно, RAM/Flash записаны в history.
- [ ] Настройки сохраняются и восстанавливаются после перезагрузки.
- [ ] Плавность и мигание `welcome_blink()` работают как раньше.
- [ ] Подготовить текст коммита (стиль проекта, по запросу).

## Риски

- **Скачок 0.9 → 2.x** — это не один API, а несколько поколений. Ошибки будут идти волной;
  разбирать по первой, а не пачкой.
- **Имя репозитория:** в разных проектах встречается и `etl`, и `ETL`; неверный URL даст
  непонятную ошибку зависимостей.
- **`platform = espressif32` без версии** — сейчас проект собирается на «том, что попалось»;
  фиксация версии может вскрыть давно скрытые проблемы.
- **Без тестов:** проверка только сборкой и глазами на плате; поэтому приёмка — по поведению,
  а не по зелёному логу.
- **Секреты:** `WIFI_SSID`/`WIFI_PASS` сейчас в `platformio.ini` открытым текстом; при желании
  вынести в отдельный ignored-файл (по образцу `ETLSecrets`), но это отдельная задача.

## Критерии готовности

- Проект собирается на `espressif32 @ ^8.0.0` и `etl@^2.0.0`.
- Настройки сохраняются в LittleFS и переживают перезагрузку.
- Управление яркостью и мигание работают на реальной плате.
- В history записаны: было/стало, RAM/Flash до и после, все встреченные ошибки и решения.
